# ReelStruct 前端工作台真实接入设计

## 背景

当前前端有两套方向并存：

- 新入口：`MainApp`、`HomeView`、`WorkspaceView`、`WorkPanel`、`AgentActionPanel`，视觉更接近 AI 工作台，但核心流程大多还是 mock。
- 旧工作台：`ReelStructWorkspace`，功能链路更完整，包含上传、结构迁移、版本对比、素材需求单、run 记录和模板库，但视觉密度和页面结构不适合作为下一版主界面。

本设计选择“保留新 UI 壳，接回真实能力”。目标不是重新做一个营销首页，而是把 ReelStruct 做成一个可信、可操作、可验收的短视频结构迁移工作台。

## 目标

第一阶段目标是让当前前端从“看起来像工作台”变成“真的能驱动核心流程”：

1. 品牌统一为 `ReelStruct`，移除 `CutFlow AI` 命名。
2. 首页只负责任务输入和进入工作台，不在未进入工作台时触发 run/template 请求。
3. 工作台上传样例视频时调用真实 `uploadSample`，展示真实视频、时长、镜头数、解析状态和错误。
4. 工作台的主要 CTA 调用真实 preview/demo 流程，结构节点和素材映射来自 API 返回，不再默认伪装成运行结果。
5. 没有真实数据时展示明确空状态，而不是用 mock 数据冒充结果。
6. 修复移动端横向溢出、长文件名溢出和按钮挤压。
7. 修复前端验证入口，保证 `npm run build` 和一个可用的静态检查命令可以通过。

## 非目标

第一阶段不做完整专业剪辑器，不做可拖拽时间线，不做多轨道编辑，不重写后端 API。

第一阶段也不把以下能力一次性迁完：

- 完整模板库编辑体验
- 完整 run 记录管理
- 批量四版本深度对比
- 复杂素材需求单编辑器
- 大规模组件库重构

这些进入第二阶段，但第一阶段需要预留清晰区域和数据边界。

## 产品定位

ReelStruct 是短视频结构迁移工作台。用户不是来浏览品牌故事，而是来完成一条明确任务：

```text
上传参考视频 / 输入任务
  -> 拆解参考视频结构
  -> 输入新商品或主题
  -> 生成迁移结构
  -> 检查素材缺口
  -> 生成 demo 或版本对比
```

因此界面应该是“安静、专业、高信息密度”的生产工具，而不是大面积 hero、装饰卡片和模糊概念展示。

## 设计系统

### 定位问题

- 叙事角色：首页是任务入口，工作台是执行界面。
- 观看距离：主要是笔记本和桌面端，移动端保证查看和轻操作，不追求完整剪辑体验。
- 视觉温度：冷静、可信、工程化，允许少量创作者工具的活力。
- 容量检查：工作台必须容纳视频、结构节点、素材映射、Agent 状态和输出版本，不能使用过大的标题和装饰间距。

### 视觉决策

- 色彩：以中性浅底、深色文本和低饱和边框为主；运行状态使用青绿或蓝色点缀；错误使用红色，警告使用琥珀色。
- 字体：标题和正文都使用系统 sans 字体，避免大段 serif 标题造成工具界面不稳定；代码、时间码和 run id 使用 mono 字体。
- 间距：使用 4px 基础单位，主要间距为 8、12、16、24、32；工作台卡片间距控制在 12-20。
- 圆角：工具卡片 8px，按钮 8px 或 pill 只用于小型状态标签；避免所有元素都大圆角。
- 阴影：减少玻璃拟态和重阴影，以边框、浅背景层级和少量 elevation 表示层级。
- 动效：只保留 hover、active、加载进度和状态切换；禁用大幅位移和装饰动画。

## 信息架构

### 首页

首页只保留三个任务：

1. 展示 ReelStruct 是什么。
2. 让用户输入迁移任务。
3. 进入工作台。

首页不展示伪视频分析结果，不加载 run 列表，不加载模板库。

推荐结构：

```text
Topbar
  - ReelStruct
  - 当前状态

Home
  - 一句话标题：短视频结构迁移工作台
  - 任务输入框
  - 开始分析按钮
  - 三个短示例任务
```

### 工作台

工作台采用三段式布局：

```text
Topbar
  - ReelStruct
  - 当前 run 状态
  - 返回首页

Stage Nav
  - 样例输入
  - 结构拆解
  - 迁移生成
  - 输出检查

Main Workspace
  - Left: Agent / task / status / controls
  - Right: video / structure / mapping / output
```

桌面端左侧宽度控制在 360-420px，右侧吃满剩余空间。移动端改成单列：阶段导航、Agent、视频、结构节点、素材映射依次堆叠。

## 组件边界

### `MainApp`

职责：

- 控制首页和工作台视图。
- 保存用户初始任务文本。
- 只在进入工作台后挂载工作台数据 hook。

不负责：

- 直接处理 API 细节。
- 维护结构节点、素材映射、run 记录等业务状态。

### `HomeView`

职责：

- 展示产品入口。
- 收集任务文本。
- 提供示例任务。

要求：

- 空输入也可以进入工作台，但工作台要显示“未填写任务”的可编辑状态。
- CTA 文案统一为“进入工作台”或“开始分析”，不要同时出现两个语义接近的主按钮。

### `WorkspaceView`

职责：

- 组合工作台主布局。
- 接收真实业务状态。
- 根据阶段显示对应主面板。

要求：

- 不直接定义 mock nodes / mock mappings。
- 没有 preview 时传递空状态给子组件。
- 阶段切换必须反映真实数据是否存在，例如没有样例时不能显示“已完成结构解析”。

### `AgentActionPanel`

职责：

- 展示用户任务、系统状态、最近执行步骤和错误。
- 发送补充指令。

第一阶段发送补充指令可以先写入本地消息，但必须标明它还没有重新触发后端。不能显示“已更新结构节点”这类未发生的结果。

### `WorkPanel`

职责：

- 展示视频、样例解析信息、结构节点、素材映射和主要操作。
- 上传视频时调用真实上传处理函数。
- 展示真实 preview 或空状态。

要求：

- 视频 URL 来自真实上传结果或用户本地预览。
- 本地 `URL.createObjectURL` 必须统一创建和释放，避免每次 render 创建新 URL。
- 长文件名必须截断，不允许撑破卡片。
- 目标素材数量不能硬编码为 18，应来自真实数据或显示 `-`。

### 后续组件

第二阶段再拆出：

- `VariantComparisonPanel`
- `MaterialRequestPanel`
- `RecentRunsPanel`
- `TemplateLibraryPanel`

这些组件不在第一阶段完整实现，但需要预留工作台区域和状态入口。

## 数据流

第一阶段数据流：

```text
HomeView taskText
  -> MainApp
  -> WorkspaceView
  -> useReelStruct
  -> uploadSample / compareOutputVariants / runDemo
  -> WorkPanel / AgentActionPanel
```

关键规则：

- `useReelStruct` 只在工作台挂载，避免首页空跑请求。
- `preview` 是结构节点和映射的唯一真实来源。
- `sampleUpload` 是视频基础信息的唯一真实来源。
- `status` 和 `error` 必须在 Agent 面板和工作区顶部同时可见。
- mock 数据只能用于示例任务按钮文案，不能用于结果面板。

## 状态设计

### 空状态

没有上传样例或没有生成 preview 时：

- 视频区显示上传引导。
- 结构区显示“上传样例并生成结构后显示”。
- 素材映射区显示“生成迁移方案后显示”。

### 加载状态

运行中：

- 主 CTA disabled。
- 状态标签展示当前步骤，例如“正在上传样例视频”“正在生成结构预览”。
- Agent 面板显示一条运行中事件。

### 错误状态

错误必须显示：

- 发生在哪个动作。
- 后端返回的可读错误。
- 下一步可执行操作，例如“检查后端服务是否在 8010 端口运行”或“重新上传视频”。

错误不能只写在控制台，也不能被 status 覆盖。

## 响应式规则

桌面端：

- 工作台左右双栏。
- 左侧 Agent sticky。
- 右侧视频卡片内部可两栏展示：视频 + 元信息。

平板端：

- 工作台改单列。
- Agent 不 sticky。
- 视频元信息移到视频下方。

移动端：

- 禁止横向滚动。
- 长文件名使用 `overflow-wrap: anywhere` 或单行截断。
- 主按钮宽度 100%。
- 视频卡片内边距减少。
- 阶段导航单列堆叠。

## 验收标准

第一阶段完成后必须满足：

1. 打开首页不会请求 `/api/runs` 和 `/api/templates`。
2. 顶部品牌显示 `ReelStruct`。
3. 进入工作台后，未上传样例时不展示伪结构结果。
4. 上传样例视频能调用真实 API，并把返回信息展示到视频和样例信息区域。
5. 生成结构后，结构节点来自 `preview.template.script_pattern`。
6. 生成结构后，素材映射来自 `preview.transfer_plan.mappings`。
7. 后端不可用时，页面展示可读错误。
8. 390px 宽移动端无横向溢出。
9. `npm run build` 通过。
10. 前端静态检查命令可运行，不再使用失效的 `next lint`。

## 分阶段实施

### 阶段一：真实能力接入和基础可用性

范围：

- 品牌统一。
- 首页停止预加载工作台数据。
- 工作台去 mock 结果。
- 上传和生成流程接真实 hook。
- 空态、加载态、错误态。
- 移动端溢出修复。
- 验证脚本修复。

### 阶段二：完整工作台能力迁移

范围：

- 版本对比。
- 批量四版 demo。
- 素材需求单。
- 最近 run 记录。
- 模板库入口。

### 阶段三：视觉收敛和组件化

范围：

- 拆分全局 CSS。
- 建立局部组件样式。
- 收敛按钮、卡片、状态标签、表单控件。
- 浏览器截图回归。

## 测试策略

第一阶段测试以真实用户路径为主：

- 构建：`npm run build`
- 静态检查：替换失效的 `next lint` 后运行新命令
- 浏览器检查：首页无后台 500 请求
- 浏览器检查：工作台空态、上传态、错误态
- 移动端检查：390px viewport 无横向溢出

如果后端未运行，前端检查仍应验证错误态是否清楚，而不是要求整条 API 链路成功。

## 开放问题

当前没有阻塞问题。第一阶段默认不引入新的 UI 库，不引入路由结构变化，不新增后端字段。

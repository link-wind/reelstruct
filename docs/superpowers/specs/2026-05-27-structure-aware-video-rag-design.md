# Structure-aware Video RAG 设计

## 背景

ReelStruct 当前已经有 `Shot Evidence Graph`、分析单元、OCR、ASR、单元理解、图谱聚合和结构迁移。但前端图谱拆解展示仍偏“证据日志”，把大量模型输出、warning、包装细节和 evidence 文本直接铺给用户，导致评审难以快速看懂：

- 样例视频到底抽出了什么结构。
- 这些结构如何迁移到新内容。
- 哪些素材能支撑结构槽位。
- 哪些槽位缺素材，以及怎么补。

RAG-Anything 和 Video-RAG 的共同启发是：多模态内容不应该只被压成一段文本，而应该先拆成可检索节点，再通过图关系和语义检索共同服务下游任务。ReelStruct 应该把这个思想迁移成面向短视频结构迁移的 `Structure-aware Video RAG`。

## 目标

本阶段目标是把 ReelStruct 的图谱拆解从“长文本展示”升级为“结构概要 + 图谱节点 + 可检索素材证据”。

用户默认看到的是精准结论，需要时再展开证据。系统内部则把样例结构和用户素材都组织成可检索节点，为后续素材补全提供稳定基础。

## 非目标

- 不直接接入 RAG-Anything 或某个 Video-RAG 仓库作为生产依赖。
- 不做完整向量数据库平台。
- 不做跨项目素材资产管理系统。
- 不在本阶段做复杂 AIGC 画面生成。
- 不把所有底层 evidence 默认展示给用户。

## 参考思想

### RAG-Anything 可借鉴点

- 多模态内容拆成节点，而不是只转成纯文本。
- 节点之间保留关系，例如文本和图片、标题和正文、局部和整体。
- 检索时同时使用结构关系和语义相似度。

映射到 ReelStruct：

- `Frame / Shot / Unit / Segment / OCR / ASR / Understanding` 都是节点。
- `belongs_to / supports / follows / contrasts / repeats / summarizes` 都是边。
- 检索时既看语义，也看时间、段落功能、包装信号和镜头关系。

### Video-RAG 可借鉴点

- 长视频不能一次性丢给模型，需要先抽取视觉、文本、音频线索。
- 关键帧、OCR、ASR、视觉摘要共同组成检索上下文。
- 检索结果需要回到具体视频片段和证据位置。

映射到 ReelStruct：

- 样例视频先拆成结构图谱。
- 用户素材先拆成素材索引。
- 结构槽位通过 RAG 检索素材节点。
- 缺口判断必须能说明“为什么匹配不足”。

## 核心概念

### 结构槽位

结构槽位是从样例图谱中抽象出来的可迁移需求，例如：

- 开头吸引镜头
- 标题卡 / 封面式开场
- 痛点说明
- 商品特写
- 使用过程
- 对比证明
- 情绪强化
- CTA 收尾

结构槽位不是固定模板，而是 AI 基于样例图谱生成的目标表达需求。

### 素材节点

素材节点来自用户上传的视频、图片或文案。一个节点至少包含：

- `node_id`
- `node_type`: video_shot / image / text / audio_segment
- `time_range`
- `visual_summary`
- `ocr_texts`
- `asr_texts`
- `tags`
- `packaging_signals`
- `usable_as`
- `source_ref`

### 槽位检索

槽位检索用结构槽位去素材索引里找候选节点。它不是简单关键词匹配，而是组合以下信号：

- 语义相似度：槽位需求和素材摘要是否接近。
- 视觉标签：是否有产品、人物、场景、动作、对比、结果画面。
- 文本证据：OCR / ASR 是否包含卖点、标题、CTA、价格、品牌。
- 包装信号：是否适合作为标题卡、贴纸卡、封面、转场页。
- 时间属性：素材片段长度是否适合目标节奏。

## 前端展示设计

### 1. 图谱概要

图谱页默认显示 5 条以内的精准概要：

- 结构类型：例如“展览海报开场 + 平台账号收尾”。
- 开头策略：例如“大标题和展览信息先建立主题”。
- 中段推进：例如“如果有更多镜头，可承接作品展示或空间浏览”。
- 节奏特征：例如“前段停留较长，后段快速收束”。
- 可迁移包装：例如“大标题、时间地点信息、账号导流卡”。

这些概要必须是中文短句，不展示原始 JSON 路径。

### 2. 图谱结构

默认展示简化图：

```text
Segment -> Unit -> Shot
```

节点颜色表达类型：

- Segment：结构段
- Unit：分析单元
- Shot：物理镜头
- Text：OCR / ASR 文本证据
- Gap：素材缺口

默认只展示 `Segment -> Unit`。用户点击后再展开到 shot 和证据。

### 3. 节点详情

点击节点后右侧展示：

- 节点一句话解释
- 关联镜头
- 关键帧
- OCR / ASR 摘要
- 关系说明
- warning

底层 evidence 默认折叠。

## 后端数据设计

新增 `GraphPresentationSummary`：

```json
{
  "headline": "展览海报式开场，账号导流式收尾",
  "summary_points": [
    "开头用大标题和展览信息建立主题。",
    "节奏以静态海报停留为主，结尾快速收束。",
    "可迁移包装包括标题卡、时间地点信息和账号导流卡。"
  ],
  "graph_nodes": [],
  "graph_edges": []
}
```

新增 `MaterialIndex`：

```json
{
  "material_id": "material_1",
  "nodes": [
    {
      "node_id": "material_1_shot_1",
      "node_type": "video_shot",
      "visual_summary": "产品在桌面上的特写",
      "ocr_texts": [],
      "asr_texts": [],
      "tags": ["产品", "特写"],
      "usable_as": ["商品特写", "封面画面"]
    }
  ]
}
```

新增 `SlotRetrievalResult`：

```json
{
  "slot_id": "slot_hook",
  "slot_label": "开头吸引镜头",
  "matches": [
    {
      "node_id": "material_1_shot_1",
      "score": 0.82,
      "reason": "画面是产品特写，适合作为开头吸引镜头。",
      "evidence": ["视觉摘要：产品在桌面上的特写"]
    }
  ],
  "gap": null
}
```

## 检索策略

第一阶段不用复杂向量库，先做轻量混合检索：

1. 规则召回：根据 `usable_as / tags / packaging_signals` 找候选。
2. 文本召回：根据 OCR、ASR、visual_summary 做关键词和简单相似度。
3. AI 重排：让模型基于槽位需求和候选素材输出匹配分数与理由。
4. 缺口判断：低于阈值时生成素材缺口。

后续再把文本向量化，引入本地向量索引或数据库。

## 缺口处理

当槽位没有合适素材时，输出结构化缺口：

```json
{
  "slot_id": "slot_product_closeup",
  "missing_asset": "商品特写镜头",
  "impact": "缺少证明产品细节的画面，中段说服力不足。",
  "fallback_strategies": [
    "从现有产品图裁切放大",
    "使用卖点字幕卡替代部分画面表达",
    "把该段从实拍证明改成文字说明"
  ]
}
```

## 实施顺序

### 阶段 1：图谱展示减负

- 后端生成 `GraphPresentationSummary`。
- 前端图谱页默认展示概要和简化图。
- evidence、OCR、ASR、warning 改为点击展开。

验收标准：

- 用户不展开详情，也能在 30 秒内理解样例结构。
- 页面默认不出现大段 evidence 文本。

### 阶段 2：素材索引

- 用户素材上传后生成 `MaterialIndex`。
- 图片、视频 shot、文案统一成素材节点。
- 每个节点保留视觉摘要、OCR、ASR、标签和可用用途。

验收标准：

- 前端能看到素材节点列表。
- 每个节点能说明可用于哪些结构槽位。

### 阶段 3：槽位检索

- 从样例结构生成目标结构槽位。
- 用槽位检索用户素材。
- 输出匹配素材、匹配理由和缺口。

验收标准：

- 每个结构槽位都有匹配结果或缺口说明。
- 匹配理由能追溯到 OCR、ASR 或视觉摘要。

### 阶段 4：补全策略

- 对缺口生成补全建议。
- 支持结构重排、字幕补全、包装补全、现有素材复用。
- AIGC 补全作为后续增强。

验收标准：

- 缺素材时系统不直接失败，而是给出可执行替代方案。

## 风险和边界

- 视频 RAG 不是问答 RAG，检索目标是结构槽位，不是自然语言问题。
- 素材匹配不能只靠语义相似度，必须结合镜头时长、包装信号和可用位置。
- AI 重排不能编造素材内容，必须引用素材节点证据。
- 前端图谱不能再次变成 evidence 大杂烩，默认层只展示结论。

## 推荐下一步

下一步优先做阶段 1：图谱展示减负。原因是它直接解决当前前端啰嗦问题，并且会把后续 RAG 所需的结构槽位和节点视图先稳定下来。

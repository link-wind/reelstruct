# ReelStruct 项目未完成问题清单

日期：2026-05-29

## 1. 总体判断

ReelStruct 已经跨过“只有概念和页面”的阶段，当前已经具备以下主链路：

- 样例视频输入、基础解析与结构拆解
- 镜头 / 分析单元 / 段落级结构展示
- OCR、ASR、抽帧、理解、图谱聚合
- 新内容输入、素材缺口识别
- 结构槽位驱动的素材检索、补全建议、时间线 patch 展示

但系统还没有形成一个稳定、统一、可规模化的闭环。当前最核心的问题不是单点功能缺失，而是以下四层还没有完全共用同一个工作模型：

1. 结构理解
2. 素材检索
3. 缺口补全
4. 结果生成

这意味着系统已经可以演示，但还不足以稳定支撑高质量评审、复杂视频样例和更强的自动迁移结果。

## 2. 当前核心矛盾

当前项目的核心矛盾可以概括为一句话：

**样例结构已经可以抽出来，但“新素材是否足以支撑目标结构”还不能稳定判断；即使判断出缺口，后续补全和结果生成也还没有完全自动闭环。**

这会体现在三个层面：

- 抽样例时，结构拆解和图谱解释已有结果，但质量和语言一致性不稳定。
- 检索素材时，已经有 RAG 和图谱命中链路，但很多判断仍偏规则和文本碰撞。
- 生成结果时，已经有补全决策和 timeline patch，但还偏“建议型”，不是“生产型”。

## 3. 已完成但仍脆弱的部分

以下能力已经具备骨架，但稳定性、准确性或可解释性仍不足，不能视为彻底完成。

### 3.1 样例解析与结构拆解

已具备：

- 视频基础信息展示
- 镜头数、时长、封面、字幕/语音概览
- 脚本/段落、节奏、包装等结构输出

当前问题：

- 长视频镜头数多时，shot 级理解和聚合容易退化。
- 抽帧失败、黑帧、极短镜头、包装页等情况会明显影响后续结构判断。
- 节奏、段落、包装三类结构在前端的边界仍不够清晰。

### 3.2 OCR / ASR / 抽帧链路

已具备：

- PaddleOCR 接入
- 轻量 ASR 方向已接入
- 抽帧 fallback、短镜头策略已有初步优化

当前问题：

- 海报大字、包装字、复杂版式 OCR 仍有漏识别和误识别。
- ASR 还没有彻底成为结构理解和素材检索的主证据源。
- 某些镜头仍会因为无可见帧或理解失败而导致后续证据链变弱。

### 3.3 图谱展示与时间线展示

已具备：

- 图谱结构摘要
- 段落时间线
- 节奏曲线与结构节点展示

当前问题：

- 图谱更像“结构摘要图”，还不是真正可操作的知识图谱视图。
- 时间线与节奏图能表达结构，但评审一眼看懂的能力还不够强。
- 图谱、AI结构、镜头证据、迁移解释之间仍有信息重复。

### 3.4 RAG 补全链路

已具备：

- `slot_query_profile`
- `material_graph`
- `graph search`
- `rerank`
- `slot_fill_decision`
- `timeline_patch`
- 前端补全链路展示

当前问题：

- 已能形成链路，但仍偏“可解释建议”，不是真正的可执行成片闭环。
- 对抽象表达的判断仍不够稳，例如情绪、信任感、使用前后对比、开头张力。

## 4. 半解决问题

以下问题已经进入实现阶段，但还没有达到可以收口的程度。

### 4.1 结构理解层仍不统一

现状：

- 系统已经开始从 shot-first 转向 unit-first。
- 但目前仍存在 shot、unit、segment 三层并行工作的混合状态。

问题：

- 数据模型复杂度上升。
- 前后端映射容易漂移。
- 用户难以形成“分析单元到底是什么”的稳定认知。

下一步：

- 明确 `segment -> unit -> shot` 的职责边界。
- 让理解、检索、迁移和展示都围绕统一主轴工作。

### 4.2 素材检索仍偏规则拼接

现状：

- 已有向量检索入口和图谱检索。
- 已支持 OCR、ASR、包装信号、标签、时长等混合打分。

问题：

- 多模态证据还没有统一为稳定的语义判断模型。
- 检索命中很多时候仍依赖 OCR 文本、标签词、槽位提示、时长等规则信号。
- `rerank` 仍以 rule-based 为主，缺少更强的 cross-modal judge。

下一步：

- 建立统一的多模态 evidence scoring。
- 升级 AI rerank / judge 层，而不是只靠规则加权。

### 4.3 缺口补全还停留在“建议层”

现状：

- 系统已能输出“复用 / 包装补位 / 字幕卡 / 请求补拍”等决策。
- timeline patch 已能映射到结构结果。

问题：

- patch 更像解释和建议，而不是严格执行到最终结果。
- 还没有稳定的“补全前 -> 补全后”差异验证。
- 还没彻底打通到可验证的 storyboard / rough cut / 输出 demo。

下一步：

- 让 timeline patch 真正作用到结果组装。
- 增加 patch 执行后的结果验证和可视化对比。

### 4.4 中文输出治理没有收口

现状：

- 前端已经做了部分本地化与字段转换。
- 部分中文化问题已有缓解。

问题：

- 上游 prompt、schema 字段、证据文本、前端映射仍然混用中英。
- 某些结构结论、包装说明、relation 描述仍会漏出英文。
- 当前是局部兜底，不是系统性治理。

下一步：

- 从模型 prompt、结构 schema、前端渲染三层统一“中文优先”策略。

## 5. 明确未解决的问题

以下问题当前仍未解决，且会直接影响项目下一阶段的价值兑现。

### 5.1 没有统一的结构覆盖率判断

问题：

- 系统已经能识别素材缺口，但还不能稳定量化“当前素材对目标结构的覆盖率”。
- 用户只能知道“缺什么”，但难以知道“缺得有多严重”。

影响：

- 难以进行结构重排的自动决策。
- 难以判断什么时候该补拍、什么时候该字幕替代、什么时候该重组现有素材。

需要补上：

- 槽位覆盖率
- 缺口等级
- 可补全性评分

### 5.2 RAG 还不是真正的长期知识底座

问题：

- 当前 material graph 更像单次请求内的临时图。
- 还不是跨项目、可复用、可持续积累的素材知识库。

影响：

- 每次都更像临时检索，不利于后续素材沉淀和历史复用。

需要补上：

- 持久化素材索引
- 更稳定的向量 / 图谱存储策略
- 素材资产级别的长期标注与复用能力

### 5.3 多模态理解尚未形成统一索引

问题：

- OCR、ASR、视觉摘要、包装信号、动作/主体标签虽然都有，但仍是并列字段，不是统一的检索与判断表示。

影响：

- 检索召回、证据对齐、解释一致性都容易受限。

需要补上：

- 多模态统一节点模型
- 统一 embedding / 统一 evidence representation
- 节点关系与时序关系协同检索

### 5.4 前端信息架构不够清晰

问题：

- AI结构、图谱结构、镜头证据、素材缺口、迁移解释、结果预览之间仍有重叠。
- 默认显示内容偏多，精准摘要不够收束。

影响：

- 评审难以在短时间内抓住系统价值。
- 功能越多，页面越容易变成“信息堆积”。

需要补上：

- 重新划分页面主线
- 默认只显示精准概要
- 把证据、链路、原始结构化字段折叠到次级层

### 5.5 缺少统一评估体系

问题：

- 当前更多依赖人工感觉判断系统是否“更好了”。
- 缺少结构拆解、缺口识别、补全决策、结果生成的量化评估指标。

影响：

- 后续优化容易失焦。
- 很难判断不同策略到底有没有提升质量。

需要补上：

- 结构拆解准确性评估
- 槽位命中 / 缺口识别评估
- 补全策略有效性评估
- 最终迁移结果的人评与结构对齐度评估

## 6. 分层问题地图

### 6.1 产品层

未收口点：

- 多样例输入后的对比和复用机制还不够强。
- 新内容输入后的“素材足不足”判断不够硬。
- 迁移结果更偏方案而不是成品。

### 6.2 理解层

未收口点：

- shot / unit / segment 主轴未统一。
- 长视频、多包装页、低信息镜头下理解不稳。
- OCR / ASR / 视觉摘要没有彻底统一成结构证据。

### 6.3 RAG / 补全层

未收口点：

- 检索偏规则拼接。
- rerank 不够强。
- 缺口补全还没有真正作用到最终结果装配。

### 6.4 前端展示层

未收口点：

- 默认信息量过大。
- 结构图、时间线、证据、解释之间重复。
- 还不够像“给评审看的系统演示面板”。

### 6.5 工程与稳定性层

未收口点：

- 外部模型服务失败、OCR 初始化问题、抽帧失败、前端进程假活等问题仍出现。
- 恢复能力、健康检查、失败回退策略不够完整。

## 7. 当前最重要的 P0 问题

以下问题建议视为 P0，优先级最高。

### P0-1 统一结构主轴

目标：

- 明确 `segment -> unit -> shot` 的职责。
- 让理解、检索、补全、展示围绕同一层次工作。

原因：

- 这是当前几乎所有复杂度上升的根源之一。

### P0-2 把 RAG 从“可演示”升级到“可信”

目标：

- 建立更稳定的多模态 evidence scoring。
- 升级 rerank / judge。
- 降低对 OCR 和规则词碰撞的依赖。

原因：

- 当前素材补全价值的上限主要卡在这里。

### P0-3 把缺口补全从建议推进到结果执行

目标：

- timeline patch 不只是展示，而是能真正驱动结果结构组装。

原因：

- 不打通这一步，系统就很难从“分析工具”升级成“迁移引擎”。

### P0-4 重构前端信息架构

目标：

- 让评审在 30 秒内看懂：
  - 抽取了什么结构
  - 当前素材支撑了什么
  - 缺了什么
  - 怎么补
  - 最终怎么生成结果

原因：

- 当前页面能展示很多信息，但还不够锋利。

### P0-5 建立最小评估体系

目标：

- 为结构拆解、RAG 命中、补全策略和结果生成建立最小可用评估指标。

原因：

- 没有评估，后续优化很容易陷入“看起来做了很多，但很难证明系统更强了”。

## 8. P1 问题

以下问题重要，但可在 P0 之后推进。

- 持久化素材知识库与向量索引策略
- 跨项目素材复用
- 更强的多样例结构对比
- 更细的节奏峰值与高潮识别
- 更完整的生成式补全策略，如背景图、配音、封面自动生成

## 9. P2 问题

以下问题适合在主链路稳定后推进。

- 更复杂的图谱交互形式
- 更细粒度的视觉风格迁移
- 大规模资产管理与版本化
- 更完整的自动成片与导出流程

## 10. 建议的下一阶段工作主线

建议后续工作只围绕以下三条主线展开，避免继续功能横向扩散。

### 主线 A：统一结构模型

目标：

- 收敛 shot / unit / segment 的职责
- 统一数据、检索、展示、迁移的结构边界

### 主线 B：强化 RAG 与素材补全

目标：

- 把 OCR / ASR / 视觉摘要 / 包装信号 / 动作主体标签统一索引
- 升级 rerank / judge
- 加入覆盖率和缺口等级
- 让 patch 真正作用到结果生成

### 主线 C：重做评审视角的前端表达

目标：

- 默认显示精准结构概要
- 用更少的字、更强的图、更清楚的链路讲清系统能力
- 把底层证据与原始结构字段折叠到次级视图

## 11. 结论

当前项目已经具备明显的系统雏形，尤其是在结构拆解、素材缺口识别和 RAG 补全链路上，已经不再是简单原型。但它还没有完成从“功能堆叠”到“统一引擎”的转换。

当前最重要的工作不是继续无边界加能力，而是收敛出一条稳定的主线：

**结构槽位 -> 素材证据 -> 缺口判断 -> 补全决策 -> 结果生成**

只有这条链真正统一、稳定、可解释，ReelStruct 才能从“结构分析工具”升级成“结构迁移引擎”。
